# 2026-08-30 踩坑记录（Git 初始化与协作）

## 1. PowerShell 路径写法
- 现象：`cd /a/Workbuddy/...` 报「找不到路径」。
- 原因：`/a/...` 是 Git Bash 写法，PowerShell 不认，被当成 `C:\a\...`。
- 解决：PowerShell 用 `A:\Workbuddy\...`。
- 教训：给命令前先确认用户用的 shell。

## 2. PowerShell 里 git 不在 PATH
- 现象：PowerShell 里 `git` 报「不是内部或外部命令」。
- 原因：WorkBuddy 自带 git 只挂在 Git Bash 的 PATH。
- 解决：`$env:PATH = "C:\Users\10990\.workbuddy\binaries\PortableGit\versions\1.2.0\cmd;" + $env:PATH`
- 教训：PowerShell 与 Git Bash 的 PATH 是分开的。

## 3. 中文提交信息变乱码
- 现象：PowerShell `git commit -m "中文"` 提交后中文成 `??` / 乱码。
- 原因：PowerShell 控制台代码页 GBK，git 按 ANSI 读 UTF-8 字节。
- 解决：在 Git Bash 提交（UTF-8 locale）；或 `git config --global i18n.commitEncoding utf-8` + 用 UTF-8 文件 `-F` 传消息。
- 教训：Windows 中文提交优先用 Git Bash。

## 4. system 级 core.autocrlf 噪音
- 现象：`git add` 冒出大量「CRLF will be replaced」警告。
- 原因：PortableGit system 级 `core.autocrlf=true`（共享配置，不该改）。
- 解决：仓库级 `git config core.autocrlf false` + `.gitattributes` 里 `eol=lf`。
- 教训：换行符统一交给 .gitattributes，别动全局。

## 5. 大文件误入库风险
- 现象：R 项目 36GB，其中 13GB `.rds`（单文件最大 2.4GB，超 GitHub 100MB 上限）。
- 原因：若按目录整体忽略 `output/`，会误伤里面的小 csv 结果表。
- 解决：按扩展名忽略（`*.rds` `*.pdf` `*.log`），保留 `.R` `.csv` `.md`。
- 教训：忽略规则「按扩展名」，不要「按目录一刀切」。

## 6. exclude/ 目录名误导
- 现象：`exclude/` 名字像「排除」，实则含 6 个必入库的备选方案 `.R` 脚本。
- 教训：命名有歧义的目录，动手前先看内容再决定是否忽略。

## 7. 命令含敏感词被安全策略误拦
- 现象：Bash 命令里出现某 shell 名称一词触发拦截。
- 解决：命令 / 提交信息避免该词，或换说法。
- 教训：报错先看是不是安全策略误报。
